## 账号与邀请

- **引导邀请**:账号库为空时每次启动都会打印(同一密钥派生,token 在整个空库期间稳定),打开即建管理员,仅可用一次。用户名限小写字母/数字/短横线、≤32 字符;密码 ≥8 位。
- **邀请同事**:管理员登录后访问 `/gw-admin` → 新建邀请(可选有效期分钟数,留空永不过期)。每条链接只显示一次、只能建一个账号;作废用「撤销」。
- **停用/启用账号**:`/gw-admin` 停用账号 —— 登录立即被拒,既有网关会话在下一个请求失效(网关不再代理,空闲中的上游随后自动停止);数据保留在 `usersRoot`,随时可重新启用。
- **密码**:存储为 scrypt(N=16384, r=8, p=1)加盐哈希;数据库文件 `stateRoot/users.json`。
- **退出**:所有账号统一访问 **`/logout`** —— 页面上点「Sign out」按钮即清除网关会话(也可收藏该地址)。dsh web 界面内的登出只作用于上游会话,网关会话要靠本页或会话过期(默认 30 天)解除;退出不影响上游实例运行与数据。

## 保留路径

网关在上游之前拦截以下路径,其余路径全部代理到当前会话用户的上游:

| 路径 | 行为 |
| --- | --- |
| `/login` | 登录页与登录提交 |
| `/logout` | 退出:GET 是确认页(退出按钮在此),POST 清除会话并跳回登录页;未登录访问 GET 直接跳登录页 |
| `/invite/<token>` | 邀请接受页(建号即登录) |
| `/gw-admin` | 网关管理台(仅管理员,页底也有 Sign out 按钮) |
| 其余所有路径 | 回退席位:代理到当前用户上游;未登录 303 → `/login` |

## 代理行为

- 每个网关会话在服务端持有对应该用户上游的 Cookie jar,浏览器只见到 `dhxgw_session`。
- 请求到达上游时 Host 改写为上游地址、`Origin`/`Referer` 剥离——上游按同源信任处理,无需 `trustedHosts`。
- SSE/长连接透传,不缓冲;仅无体的 GET/HEAD 在 401 时自动重试一次(会话过期自愈)。
- **WebSocket 透传**:dsh web 前端的流式复用连接走 `ws(s)://<同源>/api/remote.mux` 升级请求,网关以 upgrade 路由认领该精确路径,握手改写规则与 HTTP 代理一致(Host 改写、身份头剥离、服务端换取上游 Cookie),升级成功后双向拼接透传;升级请求同样享受一次 401 自愈重试。没有网关 Cookie 的升级请求直接断开。
